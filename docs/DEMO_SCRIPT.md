# 电商经营诊断助手三分钟演示

录屏前打开本地 `/demo`；不需要API密钥，不点击付费调用。静态页来自真实SQL结果，不称作“模型正在思考”。以下为讲稿，不是已经录制的视频。

## 0至30秒 说明业务任务

“这个项目不是做通用聊天机器人，而是把经营分析里的任务、数据口径和可验证结论连起来。我用Olist公开订单，做了经营变化诊断和商家履约排查两个场景。”

## 30至80秒 展示增长与体验案例

“3月商品金额环比增长15.36%，我拆成订单量和客单价贡献，并核对两项相加等于净变化。但同期延迟率从14.13%升到18.96%，低评分率也上升，所以不能只用增长判断经营健康。”

点击同月完整证据，展示月份、分母和Q01/Q02。说明“商品金额不是平台收入，描述性分解不是因果归因”。

## 80至120秒 展示具体对象与行动假设

“继续按同月窗口看商家，保留有效送达和评价样本量。这里给的是先核查谁、核查什么，不是直接处罚。我会进一步检查出库和承运链路、地区和品类结构，再用试点验证动作效果。”

返回案例二，说明同一窗口换排查目标会换榜单；模型必须看到与问题相符的候选。

## 120至155秒 展示边界与真实实现

“商家营销线索不是消费者访问，不能拿来算真实购买转化。应用在数据不足时拒答。真实模型使用受约束的工具调用，SQL负责计算，数值和来源由程序校验，原始草稿另存。”

免费入口演示：先查商家再查经营，显示两个独立窗口；不要在录屏中展示密钥、账号页面或其他个人标签页。

## 155至180秒 解释验证与限制

“我保留了四轮真实模型评测的失败和源码快照。不同轮次不是同题提升，v5修复仅做了本地回归，没有继承v4分数。目前还是个人原型，没有企业上线和实际收益。我希望展示的是如何把AI接到业务数据上，并让结果可核查。”

准备追问：为何不只用BI；多表关联为何放大金额；哪些部分由模型决定；样本门槛代价；如何证明AI带来增量价值。不会解释的实现先补懂，不靠背诵技术词。
