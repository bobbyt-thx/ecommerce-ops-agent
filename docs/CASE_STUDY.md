# 商品金额增长背后的履约与评价风险

## 业务问题

2018年3月完成订单商品金额较2月增长，是否意味着经营质量一起改善？本案例先拆增长构成，再检查体验信号和同月商家；给出待核查问题和验证计划，不把相关性包装成因果收益。

## 数据与指标口径

分析Olist公开历史订单。按下单月份选取最终状态为delivered的队列；商品金额不含运费，不是平台营收。商品、支付、评价先按各自粒度归并，再关联订单。

低评分定义为选定评价≤2分，分母是有评价的完成订单。延迟按实际送达日超过预计送达日判断，分母是日期有效的完成订单。两者样本不同，不可直接相加。

多评价按最新回答时间选择，review_id和分数确定性打破并列；缺失评价不当好评。单商家排查剔除多商家订单，避免直接归责。

## 观察事实

| 指标 | 2月 | 3月 |
| --- | ---: | ---: |
| 完成订单商品金额 BRL | 826,437.13 | 953,356.25 |
| 延迟率 | 14.13% | 18.96% |
| 低评分率 | 19.38% | 21.17% |

商品金额增加126,919.12 BRL，环比15.36%。对称量价分解中，订单量变化贡献58,735.66 BRL，商品客单价变化贡献68,183.46 BRL；两项之和等于金额净变化。这是可对账的算术拆解，不是原因识别。

延迟组与未延迟组的评价差异是进一步核查线索，但不能排除品类、地区或承运结构等因素。不能断言“延迟导致多少差评”。

## 经营判断

增长与体验恶化并存，需要分开判断。不能只汇报金额增长，也不能根据一张关联表处罚商家。先检查增长对象是否与问题订单重叠，再做可比人群分析。

同月、至少30单、按超基准延迟单量排序的首个待核查对象为匿名商家 `620c87c171fb2a6dd6e8bb4dec959fc6`：60笔有效送达订单中27笔延迟，延迟率45%；59笔有评价订单中25笔低评分，低评分率42.37%。对应工具Q01商家聚合记录可复核。排名是待核查优先级，不是责任概率。

## 行动假设与验证计划

| 待核查假设 | 下一步证据 | 判断方式 |
| --- | --- | --- |
| 特定履约链路发生问题 | 出库、承运、预计承诺与实际送达记录 | 按环节定位，不凭订单终态直接归责 |
| 品类或地区结构影响总体比例 | 相同品类、地区下的样本和评价覆盖率 | 同类比较，保留样本量及未观测因素 |
| 拟议优化可以改善体验 | 试点安排、可比对照、预先确定的指标 | 同时观察延迟、评价覆盖及业务护栏；不能仅以前后变化称因果收益 |

本项目没有实施以上干预，没有真实收益数据。贡献在于形成可复核的诊断与核查路径。

## 为什么需要目标感知的商家检索

2018-05至07，按超基准延迟单量排序，第一位是 `06a2c3af7b3aee5d69171b0e14f0ee87`；按低评分率排序，第一位则是 `2eb70248d66e0e3ef83659f71b244378`，146笔评价中66笔低评分，约45.21%。

后一家在旧延迟优先榜排第20，不在模型看到的前10家中。v5改为先在完整合格样本内按用户目标排序，再截取候选。这个失败体现的是检索目标和任务目标不一致，而不只是模型“不够聪明”。
